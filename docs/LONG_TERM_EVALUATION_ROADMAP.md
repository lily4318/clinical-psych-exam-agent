# 臨床心理師考題 Agent：企業式長期優化路線圖
更新：2026-10-19 ｜研究來源：[`ML_AGENT_RESEARCH_100_SOURCES.md`](ML_AGENT_RESEARCH_100_SOURCES.md)（100 項不同 URL）。
此文件將企業 ML/AgentOps、專業考題編製與心理計量分開，不把 ChatGPT Agent prompt 改進誤稱底層模型訓練。

## 核心目標：可靠、可追溯、可重現地產生臨床心理師國考模擬題
成功不是「每小時讓單一數字愈來愈高」，而是五層門檻一起成立。

| 軌道 | 指標 | 驗收門檻 | 資料與證據 |
|---|---|---|---|
| A. 程式回歸 | 固定規則、schema、歷屆視窗、題數與版本測試 | 無既有功能退步，重大檢查100%通過 | pytest、log、Git commit |
| B. Agent任務 | 在預設任務集完成所有要求的比例 | 先建立 baseline，再以90%作為長期任務成功率目標 | 20–50典型任務起始、重複trials、trace |
| C. 專業試題 | 獨立領域專家判定完整合格的全新試題比例 | 至少100新題驗收；點估計>=90%，**零關鍵錯誤**；另報95%信賴區間 | 與優化隔離的私有封存題本、專家盲審與分歧仲裁 |
| D. 心理計量 | 難度、鑑別度、誘答選項功能、信度、甲乙平行卷表現 | 有實際考生作答資料後訂可檢驗的閾值；無資料就不得宣稱通過 | 去識別化考生作答、適切統計與樣本數 |
| E. 運維風險 | 工具成功、來源有效、trace完整、花費、延遲、回退 | 無未授權的付費訓練或正式版本覆寫；留存追蹤 | GitHub Actions/實驗log/授權紀錄 |

**重大錯誤例**：診斷或藥理內容錯誤、存在兩個最佳答案、引用虛構來源、來源無法支持解析、錯誤標示正式核可。
**統計注意**：在100題中90題合格，雖達90%點估計，95%信賴區間下界仍低於90%；因此必須另報不確定性，不要把單一次90/100視為已達可泛化的可靠性證據。

## 資料治理
1. 「最新五個考試年度」是**新模擬考卷的歷屆考點選材視窗**，不是保證可當全新模型盲測資料。
2. 現有111–114年歷屆考點供開發／交叉驗證；115年只作**歷史診斷**，因過去版本已使用過，不得標成真正未洩漏測試集。
3. 在訓練／開發資料內再分 validation 或用 group/time cross-validation；同一題、同一命題衍生改寫、甲乙配對、同一考點密集變體必須留在相同分區。
4. 真正保留測試：由未參與開發的專家用新題與保密答案封存於公開 repo 之外；凍結候選版與評分rubric後才進行一次正式驗收。
5. 若驗收失敗，開發迴圈只使用開發資料；新一輪正式驗收應使用重新封存的資料。防止多次看測試錯題造成過度擬合。
6. 正式輸出前的每題資料：來源ID/原文片段或支持位置、版本、難度、認知層次、正解、逐項解析、盲審結果、是否有重大錯誤。

## 最終產品定義（使用者一鍵完成）

**單一使用入口、單一核心命題 Agent + Python 確定性管線。** 使用者給出 repository URL 加上「幫我做兒童版考卷」等指令後，系統應直接完成新領域專屬考點藍圖、來源查核、甲乙平行卷、必要自動 QA，並交付**兩個可開啟的 Word DOCX**（預設各20題；指定N題則各N題；各卷末尾附答案及解析）。新模擬卷不需要使用者逐題審閱或事前「正式核可」，但必須明確區分**自動產生的未經獨立專家驗證版本**與受保護的 `formal-v1.0` 正式版本。不能把聊天內文本、Stub provider、只輸出 Markdown/JSON、未通過 QA 的 Word，聲稱為已完成一鍵端到端命題。

**Agent數量由A/B實測決定，不預先拆成四個。** 先使單一命題 Agent 的完整任務成功；第二個獨立審查 Agent 只作候選，在相同開發案例比較臨床重大錯誤漏判率、誤判率、引用支持、甲乙等值、端到端成功率、延遲與成本。若獨立審查沒有明顯淨效益就不新增。日常使用可保留快速確定性檢核，免每次執行大規模離線開發評測；但未經充分驗證的新題不可因「訓練過」就省略高風險內容的必要來源查證。

## 階段與完成條件（依依賴順序，不承諾完成日期）

| 階段 | 實際可交付里程碑 | 完成標準 |
|---|---|---|
| P0 CI 基礎 | PR自動跑pytest，且保護正式版本 | GitHub Actions可啟動；全數程式測試通過，回報run及commit |
| P1 Word交付 | 既有有效甲乙卷JSON → 兩份真正DOCX | 存在/可讀/試題與答案解析完整；錯誤輸入不得假裝成功；PR #2待驗證 |
| P2 一鍵新領域命題 | 專屬兒童／成人藍圖、近5年來源、N題縮放、甲乙卷、DOCX串接 | 在真實可用的免費生成途徑上從短指令交付兩個檔案；不把原物質濫用藍圖硬套到兒童版 |
| P3 Eval驅動架構選型 | 單Agent baseline、同集雙角色A/B比較、20–50真實任務 | 公布各任務完成分子分母、臨床錯誤漏判及誤判、延遲、成本；有證據才決定是否保留獨立審查 |
| P4 專業試題正式驗收 | ≥100全新未洩漏題的獨立專家盲評 | 五項全部合格率≥90%、零重大診斷/藥理/答案/來源錯誤、另報95%信賴區間；非AI自評/pytest |
| P5 心理計量 | 真實考生作答分析 | 具實際樣本後才能評估難度、鑑別度、誘答選項、信度及平行卷實證等值 |

## 每小時循環：交付優先、測試驅動，而非每小時重訓

每輪先重讀 repository 的 `START_HERE.md`、`release/current_release.yaml`、`config/simulation_policy.yaml`、`config/ml_evaluation_policy.yaml` 與本路線圖，再比對 GitHub PR/Actions 最新狀態、上次未完成任務及風險。**每輪最多一個小而可回退的改進單元**：「取最新baseline → 只在候選分支修改 → 自動 PR pytest/可用開發任務評測 → 記錄 pass/fail、commit與成本 → 通過後才低風險合併」。發現新的 CI 錯誤就根據 log 修正，不把測試失敗說成模型能力不足，亦不要求使用者手動啟動已可自動運作的 PR CI。

保留兩條彼此獨立的進度追蹤：(a) 100來源研究索引，每輪最多3篇此前未逐項詳讀項目，分別記錄全文、部分正文或僅摘要/影片可得程度、日期、URL、限制及實際可行改進；不得把索引100筆宣稱為100篇全文已讀。(b) 企業式 AgentOps 五軌 KPI（程式回歸、端到端任務、獨立專家品質、真實考生心理計量、維運/安全/成本）；沒有資料就標為未驗證。每輪保存 prompt/模型/資料版本、baseline、分子分母、重大錯誤、費用、git commit、回退方式；禁止將公開115年資料或每小時重複的封存集稱作獨立盲測。

安全與成本：本專案使用者要求**完全零額外付費**，僅使用已確認免費的 GitHub 公開儲存庫標準 Runner、開源 Python 工具與有確切免費條件的服務。免費 Runner 不等於免費 LLM API；**不得**新增需要收費的 API、付費 Runner、微調、升級方案或其他有帳單風險功能。未取得可用免費模型生成途徑時，實話回報 P2 阻礙，不可以 Stub 或靜態舊題冒充新命題。既有 `formal-v1.0`、已核可試題答案與正式藍圖不可被覆寫；每輪只用開發資料做優化，正式封存集候選版凍結後才獨立驗收。
