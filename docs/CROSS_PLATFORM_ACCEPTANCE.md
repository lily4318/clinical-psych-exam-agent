# 跨 AI 平台執行與雙 Word 交付驗收

本文件是開發與外部冷啟動測試規格。GitHub 分享的是 Agent 的規則、知識、藍圖與工具，不是對方 AI 的模型權重；任何模型均不可假裝擁有其平台不提供的檔案／網路功能。來源以 START_HERE.md、agent/system_prompt.md、正式 release 與相關政策為準。公開 repo 一律唯讀使用，不得改寫 formal-v1.0。

## 同一份冷啟動測試指令

使用全新對話，只給 repo URL 與任務，不引用本專案的先前聊天記憶：

> https://github.com/lily4318/clinical-psych-exam-agent 請依這個 Agent 規則製作兒童／青少年臨床心理師國考甲乙各3題，兩份 Word 各附答案與解析，第一次最終回覆就提供兩個可下載附件；無法交付請明確說明。

AI 不必使用作者的 Ollama、付費模型 API 或 GitHub 寫入權限；有本機／免費可用的生成能力才可自行命題，不能冒充 Stub 為真實命題。

## 獨立六關驗收

| 關卡 | 必須觀察的結果 | 常見失敗 |
|---|---|---|
| G1 載入規則 | 實際讀取入口、政策、命題 prompt 與所需藍圖，記錄 repo commit | 只看網址卻聲稱讀完 |
| G2 命題 | 領域符合臨床心理師考試程度；甲乙各指定 N 題、未指定時各20題；近5個可取得年度動態解讀 | 把兒童版當兒童作答、直接截短20題 |
| G3 DOCX 結構 | 兩個非空可開啟 DOCX，卷別、題數、A–D、答案、解析、來源 ID、草稿標示正確 | 只有聊天文字、檔名、JSON 或假附件 |
| **G4 首次下載** | **第一次最終回覆**附兩個實際可點擊的下載連結／附件，測試者逐一點開 | 追問後才補交、sandbox 路徑不存在 |
| G5 臨床證據 | 獨立查核診斷／藥理／答案／來源支持；新題專家驗證與程式測試分開 | 用 AI 自評當獨立驗證 |
| G6 可追溯 | 平台、模型、版本、時間、附件、失敗原因和補交狀態均可查 | 只說「成功」無證據 |

**本機 G3 通過不等於 G4：**實際回覆有沒有可點的連結，需在原平台檢查。兩個附件連結都無法證明題目 G5 達標。沒有工具的 AI 應第一次就誠實回報「Word 尚未交付」，但 G4 仍為失敗。

## 供其他 AI、人工評估者共用的 G3 CLI

將雙 DOCX 放在有 Python 3.11+、python-docx 的環境，從 repository 根目錄執行：

    python -m src.verify_external_delivery form_a.docx form_b.docx --items 3 --output delivery_report.json

成功退出碼 0，失敗退出碼 1。結構性檢查包括：
- 檔案可開啟、正確卷別、版本相同、題號 1..N、每題 A–D 選項完整
- 甲乙題幹不能完全相同、兩卷都有答案與解析區段、答案表與逐題答案一致
- 正解解析及來源 ID 都有 N 項、保留未經專家驗證／非正式核可標示
- 支援本 repo 的 DOCX 輸出格式，及已取得的2026-10-21外部測試樣本格式

這是 **文件結構檢查器，不會連線查找來源、執行模型、驗證下載連結、認定臨床內容正確或推論甲乙在心理計量上等值**。JSON 報告會顯示未驗證項目。不得將測試用合成題目冒充新生成考題。

## 平台與情境矩陣

在每個實際有權操作的平台（例如 ChatGPT、Claude、Gemini）分別用新對話測試：
- T1：甲乙各3題，G1–G4，第一回覆有兩個可點附件
- T2：只說「兒童版考卷」，甲乙各20題，不先追問題數
- T3：明確指定10題，兩卷各10題，藍圖按比例縮放，不截短20題
- T4：平台無法產出 DOCX，第一次回覆明示「Word 尚未交付」並列阻礙，不偽造 sandbox 連結
- T5：讀取 formal-v1.0 或產生新草稿，都不可改寫已核可題目與正式藍圖

每次 trial 記錄：trial_id、日期時間、平台與模型（未知記 unknown）、repo commit、prompt／來源版本、使用者要求題數、首次回覆兩連結存在與否、兩連結是否實際可開、G3 JSON 結果、G5 狀態、token、成本、延遲、失敗原因、補交結果、rollback。**測試失敗後的補交不會倒算首次交付成功。**
