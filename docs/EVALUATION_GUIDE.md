# 自動優化與資料切分指南

## 目標和目前狀態

此 Agent 的優化目標是「**獨立專家判定合格的全新模擬題比例 ≥ 90%**」。每題必須同時符合：
1. 專業內容與診斷／處遇敘述正確。
2. 四選一且只有單一最佳答案。
3. 解析與引述來源足以支持正解並解釋干擾選項。
4. 符合該命題領域的考點、難度與認知藍圖。
5. 無重大事實、用藥、診斷、資料來源錯誤。

準確率計算：全部合格題數 / 已完成專家標註的總題數。使用者要求達到 90%，但在未建好獨立標註測試集前，狀態為 **尚未驗證**，不得聲稱達標。建議全新、彼此獨立的正式測試題數至少 100 題，若樣本不足需報告不確定性。

## 兩批資料（訓練／開發與獨立測試）

- **訓練／開發批**：反覆調整 prompt、來源選取、命題分配與品質驗證，可在此批內交叉驗證。
- **鎖定的獨立測試批**：測試題本、官方／專家標準答案及評分結果不能進入每小時調整的上下文。只有凍結候選版本後才使用；測試失敗後如繼續優化，應重新取得新盲測題，而非反覆針對相同測試集修正。

參考 Google ML Crash Course 的訓練／驗證／測試分離與 scikit-learn 的防洩漏做法。雖然使用者指定「兩批」，可將交叉驗證放在訓練批內；不要把最終測試批當開發集。

## 現有公開 74 筆歷屆考點資料如何切分

依 `data/historical_exam_index.csv` 的最新五個考試年度，以考試年度為群組：

| 用途 | 年度 | 筆數 | 性質 |
|---|---|---:|---|
| 訓練／開發診斷 | 111–114 | 48 | 允許反覆優化 |
| 最新年度診斷 | 115 | 14 | **非獨立盲測**；僅供報告與回歸比較 |
| 歷史保留 | 110 | 12 | 不在新題近5年視窗內，但供既有版本追溯 |

**嚴重限制**：115 年的考點已出現在公開 repo 與早先正式題目設計流程。因此 115 年即便從索引中隔離，也不等於「模型沒看過」，不能拿該 14 筆達到的成績宣稱新題品質達到 90%。這 74 筆目前主要是「考點索引＋答案狀態」，不含可完整執行的逐題原題／模型作答資料，無法直接評估國考作答準確率。

真正的獨立測試應另行由未用於提示詞開發的全新題目、未公開答案與獨立專家標註組成。測試金標準不要提交到這個公開 repo，也不要把答案傳入生成 prompt。

## 程式與輸入格式

執行：
```bash
python -m src.ml_evaluation
```
只列出可重現的歷屆年度分組數與非盲測警告；**不會**自行產生準確率。

取得獨立專家標註後，以本機另存 CSV（勿提交公開 repo）。欄位：
```csv
item_id,factually_correct,single_best_answer,rationale_supported,blueprint_aligned,no_critical_error
blind-A01,true,true,true,true,true
blind-B01,true,false,true,true,true
```
再執行：
```bash
python -m src.ml_evaluation --expert-review /path/to/private_expert_reviews.csv
```
程式提供**評分數學與資料完整性檢查**，並不能自動證明標註者真的獨立或題目沒有外洩。正式結論必須額外查核保密、來源、題目重複性及是否曾參與調參。

## 每小時迭代

依 `config/ml_evaluation_policy.yaml` 逐次執行「檢查上次基準 → 用訓練／開發集驗證 → 有證據才做低風險改善 → 留下 commit、指標和阻礙」。沒有新的實測資料時，可以做安全的程式、文件與回歸測試改善，但不得捏造訓練或評分結果。

這是一套 **prompt／應用層管線最佳化**，不是自動重新訓練 GPT 底層模型權重。若要做真正的模型 fine-tuning，另需授權 API、可合法使用的訓練資料、費用上限與專門的訓練基礎設施。

## 保護已正式核可內容

`release/formal_release_v1.0.yaml` 及所鎖定的題組不可覆寫；未獲使用者明確核可，不能替換正式考卷、答案與原來源要求。新結果只放在新的草稿／實驗版。
