# 甲乙真實命題技能
遵守 `START_HERE.md`、`config/simulation_policy.yaml`、`agent/system_prompt.md`、`docs/AGENT_ARCHITECTURE_V2.md`；先取得 `exam-evidence-blueprint` 的可核查來源與該領域藍圖。
1. 查明**實際可用且零額外付費**的推論途徑（如當前環境真可執行的Ollama或已有平台推論）。免費Actions不等於免費LLM；沒有就分類 `model_unavailable`，不能改用付費API、Stub、FakeModel或無來源假題冒充完成。
2. 預設甲乙每卷20題，指定N則各N。建立P01–PN配對，同學習目標／目標難度／認知層次，情境實質不同；**不得宣稱未經考生實測的實證等值**。
3. 每題輸出題幹、A–D四選項、單一最佳答案、正解解析及A／B／C／D各自非空解析、考點、難度、認知層次、非空去重來源ID／實際支持位置，並標記未經獨立專家驗證。
4. **先做來源命題方向對照，後決定正解**：逐題抽出來源原文的「行為／對象／時點／上限或下限／比較或否定詞」，逐字核對選項及正解解析。特別注意 `within N months`＝「N個月內」，不是「至少N個月後」；`before`、`after`、`at least`、`at most`、`must`、`may` 也不可互換。先建立「來源支持的正確命題 → 各選項判斷與獨立差異 → 答案字母」，不能因預先指定答案位置而倒推或捏造解釋。證據不支持、答案位置不符時退回重新命題／標記來源不足，不能直接交付。
5. **解析具鑑別力，不只填滿欄位**：JSON 仍需保留正解與 A–D 各自解析以利機器檢查；正確與錯誤選項若只換「正確／不正確」標籤、實質理由完全一樣，必須拒絕。多個**錯誤**選項若真正共享同一個錯誤原因，讀者版可整併為「A、C、D 共同原因」，但不可刪除各選項的判定或掩蓋不同之處；在現有 DOCX 驗證器尚未支援共同段落前，維持機器可驗證的 A–D 欄位，不冒稱整併已上線。
6. 使用現有 `src/child_exam_pipeline.py`／schema及已實作的**有限範圍**矛盾哨兵驗證兩份真JSON。已涵蓋部分「within→至少…後」顛倒及正／誤選項理由複製的明確案例，**不是**一般性的臨床語意審查；其他來源支持、診斷與藥理仍須查證，不能以單Agent自評或 pytest 當獨立專家驗收。
**完成**：真實推論證據＋甲乙各N題有效JSON及版本／來源可追溯。正式formal資料不可覆寫，缺推論就記阻礙。
