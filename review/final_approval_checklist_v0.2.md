# Final Approval Checklist｜review-v0.2

狀態：待複核  
`approved_by_user=false`

本文件定義 review-v0.2 從「人工審閱版」升為「使用者正式核可版」的唯一核可門檻。

## Canonical release

唯一核可對象為：

- `review/release_manifest_v0.2.yaml`
- 甲卷 20 題（P01–P20 form_a）
- 乙卷 20 題（P01–P20 form_b）

不得混用舊版 v0.1／v0.2 批次或其他未列入 manifest 的題目。

## 核可前必須維持的狀態

- `approved_by_user=false`
- `quality_status=待複核`
- Agent reviewer、程式驗證、考生視角 reviewer、來源核對均不能自動改成「已核可」。

## 使用者核可語句

只有明確包含「核可／正式核可／批准」且指向特定版本或卷別的訊息，才能視為核可，例如：

- `核可 review-v0.2 甲卷與乙卷`
- `正式核可 review-v0.2`
- `核可 review-v0.2 甲卷`
- `核可 P13 甲乙兩題`

以下訊息**不構成核可**：

- `繼續`
- `同意`
- `可以`
- `照這樣做`
- `下一步`
- `看起來不錯`

這些只表示同意繼續工作或同意當前流程，不得據此將任何題目改成 `approved_by_user=true`。

## 逐卷核可項目

### 甲卷

- [ ] 20 題題幹與選項已由使用者檢視
- [ ] 無雙答案或題意歧義
- [ ] 難度與國考風格可接受
- [ ] 答案位置與整體節奏可接受
- [ ] 使用者明確表示「核可 review-v0.2 甲卷」

### 乙卷

- [ ] 20 題題幹與選項已由使用者檢視
- [ ] 無雙答案或題意歧義
- [ ] 難度與國考風格可接受
- [ ] 與甲卷的平行等值性可接受
- [ ] 使用者明確表示「核可 review-v0.2 乙卷」

## 完整 release 核可

只有下列任一條件成立，才能建立完整正式核可版本：

1. 使用者分別核可甲卷與乙卷；或
2. 使用者明確表示「正式核可 review-v0.2 甲卷與乙卷／整份 review-v0.2」。

正式核可時，應建立**新的版本紀錄**，不要覆蓋 review-v0.2 的歷史審閱檔。正式版本才可設定：

- `approved_by_user=true`
- `quality_status=已核可`
- 記錄核可日期與核可範圍
